# 数据库设计

数据库名：`sky_take_out`，字符集 `utf8mb4`，共 11 张业务表。
初始化脚本见 [`database/sky_take_out.sql`](../database/sky_take_out.sql)，包含建表语句和演示数据。

## 表一览

| 表名 | 说明 | 关键字段 |
| --- | --- | --- |
| `employee` | 员工（后台账号） | `username`、`password`（MD5）、`status` 1 启用 / 0 禁用 |
| `category` | 分类 | `type` 1 菜品分类 / 2 套餐分类、`sort` 排序、`status` |
| `dish` | 菜品 | `category_id`、`price`、`image`、`status` 1 起售 / 0 停售 |
| `dish_flavor` | 菜品口味 | `dish_id`、`name`（如“辣度”）、`value`（JSON 数组字符串） |
| `setmeal` | 套餐 | `category_id`、`price`、`image`、`status` |
| `setmeal_dish` | 套餐与菜品关联 | `setmeal_id`、`dish_id`、`copies` 份数 |
| `user` | 微信用户 | `openid`、`name`、`phone`、`sex`、`avatar` |
| `address_book` | 收货地址 | `user_id`、`consignee`、`phone`、`province/city/district`、`is_default` |
| `shopping_cart` | 购物车 | `user_id`、`dish_id` / `setmeal_id`、`dish_flavor`、`number`、`amount` |
| `orders` | 订单 | `number` 订单号、`user_id`、`status`、`pay_status`、`amount`、`order_time`、`checkout_time` |
| `order_detail` | 订单明细 | `order_id`、`dish_id` / `setmeal_id`、`number`、`amount` |

## 主要关联

```
employee                      （后台独立，不与其他表关联）

category 1 ── n dish          dish 1 ── n dish_flavor
category 1 ── n setmeal       setmeal 1 ── n setmeal_dish ── 1 dish

user 1 ── n address_book
user 1 ── n shopping_cart ── n dish / setmeal
user 1 ── n orders 1 ── n order_detail
```

- 菜品、套餐都有 `status` 字段，只有起售状态才会在用户端展示。
- 删除分类前会校验是否关联菜品/套餐；删除菜品前会校验是否被套餐关联。
- 订单金额相关字段统一用 `decimal(10,2)`；时间字段为 `datetime`。

## 订单状态

| 值 | 含义 |
| --- | --- |
| 1 | 待付款 |
| 2 | 待接单 |
| 3 | 已接单 |
| 4 | 派送中 |
| 5 | 已完成 |
| 6 | 已取消 |

## Redis 中的键

| Key | 类型 | 说明 |
| --- | --- | --- |
| `SHOP_STATUS` | String | 店铺营业状态，1 营业中，0 打烊中 |
| `dish_{categoryId}` | String（JSON） | 用户端按分类查询菜品的缓存 |

> 修改菜品、起售停售、删除菜品时会清理对应的 `dish_*` 缓存；切换营业状态会更新 `SHOP_STATUS`。
